# Chat 能力

Chat 是了解产品、查看当前账户状态、搜索视频内容以及发起引导式操作的最快入口，用户不需要在多个页面之间来回切换。

## Chat 的用途

- 解释产品如何工作、某个功能位于哪个页面，以及应该使用哪个流程。
- 在多轮对话中持续推进同一项工作，而不是让用户每次都从头开始。
- 把产品帮助、实时状态读取和引导式操作集中在同一个入口里。

## 专门化能力路径

在对话表面之下，Chat 会把请求路由到不同的专门能力。用户不需要记住内部名称，但系统确实会根据请求类型切换行为。

- 产品帮助与上手引导：解释 pairing、API keys、billing、摄像头注册、AI Agents、Jobs、Steps、orchestration、应用概览以及 Chat 本身。
- 当前状态读取：列出摄像头、jobs、agents、余额、配置、最近执行记录、操作历史，以及在相关数据存在时读取持久化的 identity cards。
- 视频与图片检查：搜索一个或多个摄像头，分析用户上传的图片或视频，并通过现有的视频搜索管线回答有关录像、事件或检测的问题。
- 本地网络发现：直接从 Chat 运行 Scan Network，发现摄像头、DVR 和 NVR，并总结结果。
- 摄像头操作：注册单个摄像头、准备批量注册、编辑单个摄像头、对多个摄像头应用同一编辑，以及启动或停止现有摄像头的 runtime。
- Job 操作：创建定时 jobs 和多 step workflows，编辑已有 job，以及启动、停止、暂停或恢复某个 job 的 runtime。
- Agent 操作：在摄像头上或在 job step 内创建或编辑 agent，包括目标位置、执行频率、prompt 修改、启用或停用、negative conditions，以及在需要时处理带可视区域的流程。
- 报告：生成可下载文档，内容可以覆盖当前状态、历史、检测、告警、jobs、agents、logs、对比分析以及相关的聊天上下文。
- 直接回答：当没有更合适的专门能力时，Chat 仍然可以像普通助手一样直接回答。

## Chat 如何处理多轮工作

- 它可以在多条消息之间保持一个活动任务，而不是把每条消息都视为全新的请求。
- 当请求已经可执行但信息不完整时，它会主动索取缺失字段。
- 当目标存在歧义时，它会优先确认，而不是猜测。
- 它能够理解类似 `5 个都用同样的设置`、`那台摄像头`、`同一个地址`、`现在改成 step 版本` 这样的后续补充。
- 在摄像头批量工作流中，它可以跨多轮持续收集条目、共享默认值和编辑规则。

## 记忆与连贯性

- Chat 主要使用两类对话记忆：
  1. 最近 turns，用于保持即时连续性。
  2. 紧凑上下文，用于保存更久以前但更持久的重要信息。
- 紧凑记忆会保留摘要、用户目标、限制条件、偏好、已选择实体、已做决定以及仍未闭合的问题等持久事实。
- 它还会保存当前操作的任务记忆，包括活动任务、阶段、目标、已收集字段、缺失字段以及最近完成的任务。
- 它也会保留关键的会话实体，比如最近相关的名称或 id，以便更好地理解简短的后续消息。
- 当对话过长时，较早的消息会被压缩，只有最近的消息会保持原样。
- 如果当前消息明显改变了话题，系统会以当前消息为准。
- 紧凑记忆不应保存密码、API keys、tokens、RTSP URLs 或其他私密凭据。

## 语言行为

- Chat 面向这些受支持的 UI 语言：English、Portuguese、Spanish、French、Chinese 和 Arabic。
- 它会尽量使用用户的语言作答。
- 如果用户语言不受支持，它会回退到 English，而不是猜测一个相近语言。
- 产品 knowledge 在内部可以回退到 English，但最终回答仍然可以重写成用户的回复语言。

## 保护规则与重要限制

- Chat 不应虚构实时状态。如果答案依赖实际检查，它应该先读取真实状态。
- Chat 不应编造用户未提供的摄像头凭据、IP、端口、用户名、密码或地址。
- 某些操作依赖已连接的本地 runtime、有效的聊天会话上下文、账户中的现有数据以及产品当前启用的权限。
- 当需要最稳妥的产品解释时，系统应优先依赖本地 knowledge 文档。
- 最终回答会经过润色，以保持简洁、聚焦产品，并避免暴露实现细节。

## 推荐提问方式

- `聊天能做什么？`
- `你在这个应用里能做哪些事？`
- `列一下聊天能帮我的事情`
- `你能从这里检查我的摄像头和 jobs 吗？`
- `你能帮我创建或编辑摄像头、agents 和 jobs 吗？`
- `你怎么在多条消息之间保持上下文？`
- `你的限制是什么？`

## 实用原则

- 当用户想要以下三类事情之一时，最适合使用 Chat：
  1. 对产品能力进行可靠说明。
  2. 对当前状态、历史记录或视频内容进行读取或搜索。
  3. 一项可以在多轮对话中持续推进，直到被确认或完成的引导式操作。
