# Camera Creation

Users can register cameras from either **Cameras** or **AI Agents**.

For explanations and for the guided tutorial, use **Cameras** as the main example page, but make it clear that the same discovery, import, and manual-registration options are also available from **AI Agents**.

## Where cameras can be registered

- **Cameras**
- **AI Agents**

Both pages expose the same three entry paths:

1. **Scan Network**
2. **Import Cameras**
3. **Register Camera** manually

## Fastest ways to onboard cameras

### Scan Network

- **Scan Network** searches the local network for cameras and **NVR/DVR** devices.
- This is usually the easiest option when the devices are already reachable on the same network.
- If the user asks for the easiest path, recommend this first.

### Import Cameras

- **Import Cameras** accepts **Excel**, **CSV**, **JSON**, **TSV**, and **plain text**.
- The local AI reads the columns or free-form fields and registers the cameras automatically.
- Recommend this when the user already has an exported inventory, spreadsheet, installer handoff, or camera list from another system.

## Manual camera registration

If the user wants full control, they can click the manual camera-registration button in **Cameras** or in **AI Agents**.

The manual form lets the user choose between:

1. **IP / RTSP camera**
2. **Webcam**

## IP / RTSP camera flow

Use this flow for cameras such as **Hikvision**, **Dahua**, and **Intelbras**.

The form covers:

- **Camera name**
- **IP address**
- **RTSP port**
- **Manufacturer**
- **Connection method** such as RTSP, HTTP, or ONVIF
- **Username**
- **Password**
- **Channel**
- **Subtype**

Important vendor notes:

- For **Hikvision**, change **Channel** to reach other channels.
- For **Intelbras**, use **Subtype** to reach other channels.

## Address section

After the connection fields, the form continues with the camera address.

- The address flow starts with **ZIP code / CEP**.
- After the user enters the CEP, the app can auto-fill **street**, **city**, and **state**.
- The field that usually still needs manual confirmation is the **street number**.

## Retention

- **Retention** defines how long the frames generated by that camera stay stored on disk.
- This controls how much history remains available for past review and search.

## Collaborator Sharing

- **Collaborator Sharing** lets the user share the camera with specific Perceptrum users invited by `@handle` or email so they can use it in Drakon Find.
- Explain this as intentional sharing with collaborators, not as public exposure.

## Webcam flow

**Webcam** is the simpler manual path.

Webcam still uses the shared operational fields:

- **Camera name**
- **Address**
- **Retention**
- **Collaborator Sharing**

The main webcam-specific field is:

- **Webcam index**, which is usually `0`

Unlike IP / RTSP cameras, webcams do **not** require:

- IP address
- port
- manufacturer
- username
- password
- channel
- subtype

## What both manual flows share

Both **IP / RTSP** and **Webcam** share:

- camera name
- address
- retention
- collaborator sharing

The difference is that **IP / RTSP** needs transport and vendor fields, while **Webcam** usually only needs the webcam index.

## Guided tutorial behavior for camera registration

When the user asks about the guided tutorial camera step:

- Explain it using the **Cameras** page as the visual example.
- Also mention that the same actions are available in **AI Agents**.
- The tutorial first highlights the top shortcuts:
  - **Scan Network**
  - **Import Cameras**
  - **Register Camera**
- Then it opens the manual form and clearly explains the **IP / RTSP** tab:
  - camera name
  - IP address
  - port
  - manufacturer
  - username
  - password
  - channel
  - subtype
  - address
  - retention
  - collaborator sharing
- After the RTSP/IP explanation, the tutorial switches automatically to **Webcam**.
- In that example flow, the tutorial fills:
  - webcam index `0`
  - camera name `tutorial webcam`
- Then it saves that webcam example and continues to the next tutorial stage.

## Practical recommendation

Recommend the paths in this order:

1. **Scan Network** when the devices are already on the network
2. **Import Cameras** when the user already has a file
3. **Manual registration** when the user wants one-by-one control
