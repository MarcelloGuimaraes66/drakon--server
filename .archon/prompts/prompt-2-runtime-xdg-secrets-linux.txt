Implementar nesta fase:

A. Runtime roots Linux/XDG
1. Garantir que o Linux respeite:
   - APP_RUNTIME_DATA_ROOT
   - APP_RUNTIME_CONFIG_ROOT
   - APP_RUNTIME_CACHE_ROOT
   - APP_RUNTIME_STATE_ROOT
   - APP_RUNTIME_LOG_ROOT
2. Garantir fallback XDG correto quando os overrides não existirem:
   - dados em ~/.local/share/PerceptrumData ou equivalente definido por brand.config.json;
   - config em ~/.config/Perceptrum ou equivalente;
   - cache em ~/.cache/Perceptrum;
   - state/logs em local gravável adequado.
3. Criar diretórios automaticamente quando necessário.
4. Não escrever dentro do diretório instalado.
5. Não falhar se HOME estiver read-only quando APP_RUNTIME_* apontar para /tmp.

B. Logs e health snapshot
1. Garantir diretório de logs em APP_RUNTIME_LOG_ROOT.
2. Garantir escrita de agent_health.json em APP_RUNTIME_DATA_ROOT.
3. Implementar ou validar campos mínimos do health:
   - version;
   - status;
   - paired;
   - base_url;
   - client_id sem secret;
   - pid;
   - heartbeat_unix_ms;
   - heartbeat_utc;
   - runtime_timezone;
   - data_root;
   - config_root;
   - log_root.
4. O comando status deve ler do mesmo runtime root usado pelo run.
5. O comando healthcheck deve:
   - retornar sucesso apenas quando saudável;
   - retornar erro funcional claro quando not_paired;
   - não tratar not_paired como crash.

C. Segurança de secrets Linux
1. Auditar platform_secure_store no Linux.
2. Se o caminho Linux ainda gravar secrets em plaintext por padrão, corrigir para fail-closed quando a política exigir segredo protegido.
3. Se libsecret/secret-tool não estiver disponível, permitir somente fallback explícito via variável clara, por exemplo:
   - APP_ALLOW_PLAINTEXT_SECRET_RECOVERY=1
   - PERCEPTRUM_ALLOW_PLAINTEXT_SECRET_RECOVERY=1
4. Garantir permissões seguras quando arquivo local for usado:
   - diretório 0700;
   - arquivo 0600.
5. Não imprimir secrets em logs.
6. Não retornar plaintext silenciosamente.
7. Não quebrar DPAPI/Windows.
8. Não quebrar macOS; se macOS ainda não tiver keychain implementado, deixar caminho isolado e documentado.

D. Testes mínimos CTest
Adicionar testes CTest mínimos para a base Linux:
1. perceptrum-agent --help.
2. perceptrum-agent validate-config com APP_RUNTIME_* em /tmp.
3. perceptrum-agent check-deps com APP_RUNTIME_* em /tmp.
4. perceptrum-agent version, se existir.
5. perceptrum-agent status sem snapshot deve retornar erro funcional controlado ou saída válida, mas não crash.
6. timeout curto do run, se seguro, validando que cria agent_health.json.
7. healthcheck com not_paired deve ser validado como estado funcional esperado, não crash.

E. Desktop stub
1. Manter perceptrum-desktop como stub ou shell inicial.
2. Garantir que ele respeite APP_RUNTIME_*.
3. Não avançar para telas completas ainda.
4. Não tentar paridade visual nesta fase.

F. CMake
1. Atualizar Perceptrum/CMakeLists.txt somente se necessário.
2. Não globar arquivos indiscriminadamente.
3. Manter lista explícita de fontes.
4. Excluir AppHost, WinUI, .vcxproj, .sln, arquivos *_old.cpp e UI Windows-only.
5. Não tocar nos projetos Windows.
