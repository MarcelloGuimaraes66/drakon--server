Implementar nesta fase:

A. Interfaces portáveis mínimas
Criar uma pasta canônica para contratos portáveis, por exemplo:

Perceptrum/Perceptrum/runtime/interfaces/

ou outro local justificado no relatório.

Criar interfaces mínimas, se fizer sentido:
1. IRuntimeLogger
   - info()
   - warn()
   - error()
   - debug(), se útil
   - sem depender de Logger singleton global
   - sem paths hardcoded

2. ITokenStore
   - readToken()
   - writeToken()
   - hasToken()
   - clearToken(), se útil
   - nunca expor token em string de log
   - deve permitir implementação Linux usando platform_secure_store

3. IAgentCoreFactory ou IAgentRuntime
   - create/start/stop/status de AgentCore
   - nesta fase pode ter implementação stub/no-op
   - deve declarar claramente camera/jobs desativados
   - não deve puxar AgentCore.cpp para o build Linux ainda se isso quebrar o escopo

4. IHeadlessRuntime ou HeadlessRuntimeContext
   - runtime roots
   - config
   - health writer
   - logger
   - token store
   - shutdown flag
   - status callback

Objetivo das interfaces:
Permitir que HeadlessService.cpp seja gradualmente desacoplado de Logger::instance(), AgentCore direto e paths hardcoded.

B. Logging com roots explícitos
Refatorar Logging somente no menor escopo possível:
1. Não quebrar Windows.
2. Preservar Logger::instance() para Windows/fluxo legado.
3. Adicionar uma implementação ou adaptador Linux de logger com root explícito.
4. O logger Linux deve escrever em APP_RUNTIME_LOG_ROOT.
5. Não usar `logs/agent.log` relativo ao CWD no caminho Linux novo.
6. Não ler client_id.txt, exe_token.txt ou exe_id.txt relativos ao CWD no caminho Linux novo.
7. Não exportar logs ao backend usando bearer token em caminhos de teste/stub.
8. Não imprimir secrets.

C. HeadlessService preparado para dependências injetáveis
Modificar HeadlessService.h/.cpp somente se possível com baixo risco:
1. Adicionar overload, options ou construtor que aceite interfaces/stubs.
2. Preservar construtor/uso antigo para Windows.
3. Proteger mudanças com compatibilidade.
4. Não remover AgentCore real.
5. Não alterar comportamento Windows.
6. Permitir que o Linux compile uma variante que não instancia AgentCore real.
7. Se HeadlessService.cpp ainda não puder entrar no build Linux, criar relatório preciso e preparar headers/interfaces para próxima fase.

D. LinuxHeadlessRuntime
Atualizar LinuxHeadlessRuntime para usar as novas interfaces onde fizer sentido:
1. usar IRuntimeLogger ou adaptador equivalente;
2. usar ITokenStore ou adaptador equivalente;
3. manter run/status/healthcheck funcionando;
4. manter runtime_stub/headless_blocked_by_platform_coupling enquanto AgentCore real não estiver ativo;
5. não regredir testes.
